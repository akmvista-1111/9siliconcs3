# ILA 3-1: Applying the Four Pillars of OOP

## Sari-Sari Store Inventory System

### 1. Encapsulation
Encapsulation groups together variables and methods to form one object. This concept can be applied in sari-sari store inventory systems because a "Product" object can have information like product name, price, and quantity, as well as methods like addStock() and removeStock(). This makes it easier to organize the inventory because it keeps product information organized by grouping them together.

### 2. Abstraction
Abstraction hides irrelevant details, making the model simpler. This concept can be applied in sari-sari store inventory systems because simple methods like addProduct() and sellProduct() can be used without knowing the function of it internally. This makes the program easier to use and maintain.

### 3. Inheritance
Inheritance allows an object to get the properties and methods of an existing parent object. This concept can be applied in sari-sari store inventory systems because they can extend general objects like "Product" into FoodProduct and HygieneProduct. These objects can reuse the common product information like product name, price, and quantity while adding features that are specific to their type.

### 4. Polymorphism
Polymorphism allows objects to take on different forms and behave differently. This concept can be applied in sari-sari store inventory systems because each object could display information differently. For example, FoodProduct and HygieneProduct can both have a displayDetails() method which makes the program more flexible. 

## Reflection
In my opinion, Encapsulation is the most useful pillar for the sari-sari store inventory system. This pillar keeps product name, price, and quantity together in one object. Because of this, the system is easier to organize and manage.
